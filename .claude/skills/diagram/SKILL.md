# Диаграмма в документе

Диаграмма хранится в документе как текст (```mermaid), правится вместе с ним и проверяется командой.

## 1. Выбор типа — по форме содержания

| Что показываем | Тип Mermaid |
|---|---|
| Процесс с ветвлениями: что делает пользователь или система | `flowchart LR` (длинная цепочка — `TD`) |
| Статусы и переходы: аномалия, заявка, подписка | `stateDiagram-v2` |
| Кто кому что передаёт по шагам: приложение, бэкенд, АвтоГРАФ, LLM | `sequenceDiagram` |
| Путь клиента с оценкой этапов (CJM) | `journey` |
| План со сроками и зависимостями | `gantt` или `timeline` |
| Приоритизация по двум осям (ценность × сложность) | `quadrantChart` |

Список шагов без ветвлений — нумерованный список, не диаграмма.

## 2. Правила

- Источник — только документ: каждый узел и стрелка подтверждаются текстом BRD или исходника. Нового не выдумывать.
- До 15 узлов. Больше — разбить на две диаграммы.
- Подписи по-русски в кавычках: `A["Карточка аномалии"]`; у состояний — `state "Новая" as N`.
- Идентификаторы узлов — латиницей, короткие: `N`, `Push`, `Card`.
- Под диаграммой — одно предложение: что из неё следует или что на ней не показано.
- Диаграмма заменяет текст, который рисует, или дополняет его. Таблицу с теми же данными не дублировать.

## 3. Проверка

1. `npm run check -- <файл>` — статическая проверка: тип, скобки, кавычки.
2. `npm run render -- <файл>` — отрисовка в браузере. ВЕРДИКТ: ПРОШЛО. «НЕ ПРОВЕРЕНО» (нет сети или браузера) —
   сказать пользователю, а не считать пройденным.
3. Содержание документа изменилось — поднять версию в шапке.
