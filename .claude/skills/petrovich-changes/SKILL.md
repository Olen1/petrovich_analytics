# Журнал изменений `../petrovich`

Журнал — `doc/petrovich_changes.md`. Скилл дописывает в него только то, что появилось после прошлого запуска.
Код `../petrovich` не правится, коммиты и push не делаются.

## 1. Откуда начинать

1. Прочитайте шапку журнала: строка `Учтено до коммита: \`<hash>\`` — последний разобранный коммит.
   Журнала нет — заведите его по шаблону из п. 4 и разбирайте всю историю.
2. Обновите сведения о сервере: `git -C ../petrovich fetch --quiet origin`. Нет сети — работайте по локальной
   истории и напишите в отчёте «НЕ ПРОВЕРЕНО: fetch не прошёл, разобрана локальная история».
3. Ветка — `origin/main` (если её нет — `main`). Pull и checkout не делайте: рабочая копия коллег не трогается.
4. Список новых коммитов:
   ```
   git -C ../petrovich log --reverse --date=short --format="%h|%ad|%an|%s" <hash>..origin/main
   ```
   Пусто — в журнал ничего не пишите, ответьте «новых изменений нет, последний — `<hash>`».

## 2. Что смотреть в каждом коммите

- `git -C ../petrovich show --stat --format="%h %ad %an%n%B" --date=short <hash>` — состав и сообщение.
- Мердж-коммиты (`Merge pull request #N`) — не отдельная запись: по ним группируйте коммиты в PR.
  Номер PR и ветку берите из сообщения.
- Сообщение коммита не описывает суть («Upd», «правки экранов») — смотрите дифф:
  `git -C ../petrovich show <hash> -- <файл>`. Большие диффы читайте по файлам, не целиком.
- Области по путям:

  | Путь | Область |
  |---|---|
  | `app/src/main/java/ru/petrovich/telemetry/ui/<экран>/`, `app/src/main/res/` | Экраны приложения (папка = экран: `home`, `park`, `problems`, `resolution`, `chat`, `report`…) |
  | `…/telemetry/data/`, `…/telemetry/anomaly/`, `…/telemetry/chat/` | Данные приложения, связь со стендом и AutoGRAPH |
  | `ml/fleet_service/` | Стенд: `rules/` — правила аномалий, `analytics/`, `agent/` и `prompts/` — ассистент, `background/`, `mail/`, `store/`, `api/` |
  | `ml/predictive_antifraud/` | ML-модель антифрода |
  | `scripts/`, `gradle/`, `*.gradle.kts`, `.gitignore` | Сборка и окружение |
  | `README.md`, `ml/docs/` | Документация кода |
  | `app/src/test/`, `ml/*/tests/`, `testdata/` | Тесты и тестовые данные |

  Путей нет в таблице — определите область по содержимому и допишите строку в эту таблицу.

## 3. Как записать

Одна запись — один PR или, без PR, один рабочий день одного автора. Новые записи — сверху.

```
### 2026-10-09 · PR #4 `fleet/step-6` · Knohhon, LysenkoKris
Коммиты: `4202658`, `a667863`, `12636b3`

**Что изменилось**
- Стенд: фоновая обработка телеметрии; аномалии считаются без открытого приложения.
- Экраны: закрытие разбора отправляет решение на стенд (AnomalySync).
- Уведомления: отправка писем.

**Затрагивает аналитику**
- `mvp_description.md` v0.1 — не описана отправка решения на стенд.
- BRD §4.2 — e-mail-уведомления: в BRD [приоритет C], в коде уже есть → вопрос PO.
```

Правила записи:
- Язык продукта, не кода: «владелец закрывает разбор — решение уходит на стенд», а не «добавлен метод
  `syncResolution()`». Имя класса или метода — только если без него непонятно, в обратных кавычках.
- Только то, что видно в коммитах. Назначение не понятно из кода — пишите «назначение не ясно из кода»,
  не додумывайте.
- **Затрагивает аналитику** — сверьте с `doc/mvp_description.md`, `doc/mobile_analytics_screens.md`,
  `doc/brd_petrovich_mvp_full.md` (поиском по ключевым словам, не чтением целиком). Расхождение — строкой
  со ссылкой на документ с версией. Сами документы не правьте: предложите пользователю отдельно.
  Нечего сверять (сборка, рефакторинг) — «не затрагивает».
- Ссылка на документ аналитики в записи — с версией на момент записи: `` `mobile_analytics_screens.md` (версия 1.0
  на момент записи) ``. Формат `` `файл.md` v1.0 `` не годится: после следующего обновления документа
  `npm run check` сочтёт ссылку устаревшей, хотя запись историческая.
- Сверяйте прежде всего с `doc/app_implementation.md` — что уже сделано в коде. Новое в коде — допишите туда
  и поднимите версию; расхождение с требованиями — строкой в BRD §7.5.
- Ссылка на `.md`-файл из кода — с префиксом `../petrovich/`: `` `../petrovich/ml/ANALYTICS.md` ``.
  Без префикса `npm run check` ищет файл в этом репозитории и падает.
- Секреты, логины и адреса стендов из диффа в журнал не переносите.

## 4. Шапка журнала

```
# Журнал изменений кода «Петровича»
_Статус: рабочий журнал | Версия: 1.N | Дата: <сегодня>_

Что менялось в репозитории `../petrovich` (github.com/ErmakovDenis/petrovich), по PR и дням, новые сверху.
Заполняется скиллом `/petrovich-changes`.

Учтено до коммита: `<hash>` (origin/main, <дата коммита>)
```

После дописывания: замените хеш в строке «Учтено до коммита» на последний разобранный коммит, поднимите
версию на +0.1 и поставьте сегодняшнюю дату.

## 5. Завершение

1. `npm run check -- doc/petrovich_changes.md` — должен пройти.
2. Ответ пользователю: сколько коммитов разобрано, диапазон `<старый>..<новый>`, 3–5 главных изменений
   и список документов аналитики, которые отстали от кода. Сам журнал в ответ не копируйте.
