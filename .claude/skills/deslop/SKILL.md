# Антислоп

Цель — текст, который читается как написанный аналитиком: факт, число, вывод. Смысл, числа, гипотезы
в `[скобках]` и ссылки не меняются.

## 1. Автоматические маркеры

Запустите `npm run slop -- <файл>` (для слайдов — `slides/<имя>.json`). Для каждой находки:
- **ОШИБКА** — исправить обязательно, подсказка в отчёте говорит как.
- **мягкий** — исправить, если есть чем заменить: числом, конкретным действием, простым словом.
  Термин оставить («уникальных значений» в анализе данных — не слоп).

## 2. Чего скрипт не ловит — проверить глазами

1. **Тройки.** «Быстро, просто и надёжно» — оставить одно, подтверждённое фактом.
2. **Зеркальные пары.** «Не только экономит время, но и…», «X — это про Y». Сказать прямо.
3. **Вывод в конце каждого раздела**, повторяющий раздел. Удалить; вывод — первым предложением.
4. **Риторические вопросы** в заголовках и тексте. Заменить утверждением.
5. **Обобщения без субъекта и числа**: «пользователи ценят», «рынок растёт». Кто, сколько, источник —
   или в «Открытые вопросы».
6. **Тире-цепочки**: больше одного тире в предложении. Разбить на два предложения.
7. **Жирный через слово.** Жирным — только то, что читатель должен увидеть при беглом просмотре: 1–2 места на раздел.
8. **Эмодзи** в заголовках и тексте. Допустимы только индикаторы серьёзности 🔴🟡🟢, где они есть в BRD.
9. **Английские кальки**: «на ежедневной основе», «сделать фокус», «в моменте». По-русски проще.

## 3. Проверка

`npm run slop -- <файл>` — ВЕРДИКТ: ПРОШЛО. Пользователю: сколько правок, что вынесено в открытые вопросы.
Новый частый оборот, который скрипт пропустил, — предложите добавить в `scripts/lib/slop.mjs`.
