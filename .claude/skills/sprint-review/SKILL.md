# Отчёт по спринту (.pptx по шаблону)

Колода показывает, **что команда сделала за спринт и что дальше** — языком владельца парка и заказчика.
Шаблон — `slides/Петрович_итоги_1_спринта_v11.pptx`, его копия для сборки — `scripts/sprint/template.pptx`.
Эталон в нашем формате — `slides/sprint_1.json`: тот же отчёт, переведённый в JSON. Новую колоду начинайте с его
копии и меняйте содержание, а не вёрстку.

Источник один — `slides/sprint_<N>.json`. Из него команда собирает `slides/sprint_<N>.pptx` и
`slides/sprint_<N>.preview.html`. Оба файла руками не правятся: правка в PowerPoint пропадёт при следующей сборке.
Код `../petrovich` не правится, pull, checkout, коммиты и push не делаются.

## 1. Границы спринта

Нужны номер спринта и диапазон коммитов.
1. Есть прошлая колода `slides/sprint_<N-1>.json` — начало берите из её поля `sprint.to`.
2. Пользователь назвал даты — коммиты по датам:
   `git -C ../petrovich log origin/main --first-parent --since=<ГГГГ-ММ-ДД> --until=<ГГГГ-ММ-ДД 23:59> --format="%h|%ad|%an|%s" --date=short`.
3. Ничего из этого нет — спросите номер спринта и даты. Не угадывайте: границы спринта в коде не записаны.

Перед разбором: `git -C ../petrovich fetch --quiet origin`. Не прошёл — работайте по локальной истории и
напишите в ответе «НЕ ПРОВЕРЕНО: fetch не прошёл».

## 2. Факты

1. Журнал `doc/petrovich_changes.md`: «Учтено до коммита» раньше конца спринта — сначала выполните
   `/petrovich-changes`. Записи журнала за диапазон — основа слайдов: они уже на языке продукта.
2. Состав: `git -C ../petrovich log --reverse --format="%h|%ad|%an|%s" --date=short <from>..<to>` — коммиты,
   авторы, PR (по мерджам «Merge pull request #N»). Ветки без мерджа: `git -C ../petrovich branch -r --no-merged origin/main`.
3. Неясная суть — дифф по файлу (`git -C ../petrovich show <hash> -- <файл>`), как в `/petrovich-changes` §2.
4. Тесты: какие добавлены (`app/src/test/`, `ml/*/tests/`). Запускать не нужно; на слайде — «тесты добавлены»,
   «187 тестов (отчёт: зелёные)» — только если есть отчёт прогона.
5. Аналитика за спринт — из `doc/` и `DECISIONS.md` по датам: BRD, экраны, исследования, тесты с пользователями.

Инкремент кода — то, что смержено в `origin/main` до `<to>`. Сделано в ветке — пишите «в ветке, в main не влито»
(так в шаблоне: «ветки fleet/step-1…4»), не выдавайте за готовое.

## 3. План против факта

- План — слайд «Задачи на N спринт» прошлой колоды (`slides/sprint_<N-1>.json`, слайд типа `columns` с `lead`).
  Нет прошлой колоды — план из запроса пользователя или BRD `doc/brd_petrovich_mvp_full.md` §8.2 и §8.3 (DoD).
- Каждый пункт плана получает статус: `Сделано`, `Частично`, `Не сделано`, `Сделано иначе` или `Спринт N+1`
  (перенесён). Цвет плашки ставится по первому слову: сделано — зелёный, частично и перенос — жёлтый,
  не сделано — красный, иначе — синий. Основание — коммит, PR или документ — в `source` слайда.
- Счёт в тёмной панели — «сделано / всего пунктов плана», как «6 / 7 задач сделано». Сделанное сверх плана —
  отдельной строкой со статусом `Сделано`, в счёт не входит: допишите в заметки.
- Приоритеты не меняйте: расхождение с BRD — в заметки и в ответ пользователю как вопрос PO.

## 4. Колода

16 слайдов по шаблону; 10–18 — норма. Слайды контекста (3–9) в каждом спринте не пересобираются с нуля:
берите из прошлой колоды и обновляйте, что изменилось. Без изменений и аудитория та же — слайд можно убрать.

| # | type | Что на слайде |
|---|---|---|
| 1 | `cover` | Продукт одной фразой; `label` — «Итоги N спринта»; `meta` — заказчик и месяц |
| 2 | `summary` | Итоги: пункты плана со статусами, счёт, 3–5 главных задач следующего спринта |
| 3 | `panel` | Боль клиента: кто клиент и его вопросы — в тёмной панели, 2–4 боли карточками |
| 4 | `compare` | Ценность: цель MVP и «как сейчас → как с Петровичем» |
| 5 | `chat` | Чат-бот: пример диалога, 6 возможностей, «так не надо / так надо» |
| 6 | `findings` | Исследования: что узнали → что это значит для приложения |
| 7 | `table` + `side` | Сравнение с аналогами: таблица «+ / −» и карточки рейтингов |
| 8 | `columns` (2) | Гипотезы П… и Т…; со 2-го спринта в `sub` — итог: `[[ok:Подтверждена]]`, `[[high:Не подтвердилась]]`, `[[med:Проверяем]]` |
| 9 | `table` | Метрики: метрика, цель, как проверим; со 2-го спринта — столбец «Факт» |
| 10 | `progress` | Что сделали в приложении: нумерованный список, справа «под капотом», внизу 2–3 числа |
| 11 | `progress` | Что сделали в чат-боте и на сервере: шаги с пояснением, справа «Спринт N+1» и ограничения |
| 12 | `screens` | Экраны, которые появились или изменились за спринт (до 5), снизу — что изменилось |
| 13 | `flow` | Архитектура: приложение → сервер (модули «сделано» / «план») → внешние системы |
| 14 | `table` | Стек и почему так — только если менялся |
| 15 | `columns` (3) + `lead` | Задачи на следующий спринт: цель на тёмной плашке, 3 направления по 4 задачи |
| 16 | `team` | Команда: фото, имя, роль |

Защита спринта перед PO — добавьте после 13-го: демо-сценарий (`progress`, `rows` — 4–6 шагов строками:
экран и кнопка, режим демо или стенд), «что не вошло и техдолг» (`findings`: что → почему → что делаем),
«вопросы PO» (`findings`: вопрос → что нужно решить → к какому сроку).

Шапка JSON:

```json
{
  "title": "Петрович: итоги N спринта",
  "format": "pptx",
  "sources": ["doc/brd_petrovich_mvp_full.md vX.Y", "doc/petrovich_changes.md vX.Y"],
  "sprint": { "num": N, "from": "<hash>", "to": "<hash>", "dates": "ГГГГ-ММ-ДД – ГГГГ-ММ-ДД", "branches": "… не влиты в main" },
  "slides": [ … ]
}
```

`"format": "pptx"` обязателен: по нему `npm run check` отличает отчёт от HTML-колод `/doc-slides`.
`sprint.to` — начало следующей колоды. В `sources` — только `.md` с текущими версиями: `npm run check` их сверяет.

## 5. Типы слайдов

У каждого слайда: `type`, `title` (до 70 знаков, вывод, а не тема), `notes` — **обязательно**, `source` — строка
источника внизу (необязательно у `cover` и `team`). В тексте: `**жирный**`, `\n` — новый абзац, метки
`[[ok:…]]` (зелёная), `[[med:…]]` (жёлтая), `[[high:…]]` (красная), `[[low:…]]` (синяя). Тон — `green`,
`blue`, `purple`, `red`, `amber`, `gray`.

| type | Поля | Пределы |
|---|---|---|
| `cover` | title (можно с `\n`), subtitle, label, meta | — |
| `summary` | rows: [[задача, деталь, статус]], score: [число, подпись], next: {title, items} | 1–7 строк, next ≤ 5 |
| `panel` | panel: {kicker, head, text, kicker2, lines[]}, heading, accent, cards: [[заголовок, текст]] | 2–4 карточки |
| `compare` | lead, head: [было, стало], rows: [[было, стало]] | 2–5 строк, с lead — до 4 |
| `chat` | dialog: {question, answer, actions[2], fallback}, features: [[заголовок, текст]], voice: {title, dont, do} | 2–6 возможностей |
| `findings` | head: [слева, справа], rows: [[заголовок, пояснение, вывод]] | 2–5 строк |
| `table` | head, rows, widths (доли), size (кегль, 12.5), note, side: [{head, big, meta, text, tone}] | ≤ 9 строк, ≤ 2 карточки |
| `columns` | lead, columns: [{title, tone, items: [[метка, текст, sub]]}] | 2 колонки по ≤ 5 или 3 по ≤ 4; пустая метка — номер |
| `progress` | heading, rows: строки или [[название, пояснение]], stats: [[число, подпись]], side: [{title, tone, items[] или text}] | ≤ 7 строк, ≤ 3 числа, ≤ 2 блока |
| `screens` | items: [[путь к картинке, название, подпись]], note | 1–5 экранов |
| `flow` | client: {title, items}, link, server: {title, items: [[модуль, "done" или "plan"]]}, external: [[название, роль]], legend, note | ≤ 6 модулей, ≤ 3 системы |
| `team` | members: [[фото, имя, роль]] | ≤ 6 |

Картинки — в `slides/assets/` (логотип, `team/`, `screens/`), путь от корня проекта. Скриншоты экранов —
вертикальные 780×1688; другие пропорции обрезаются по центру. Новые макеты пользователь присылает файлом —
положите в `slides/assets/screens/` под латинским именем.

Не влезает — сократите текст или разбейте слайд. Шаблон и `scripts/sprint/` ради одного слайда не меняются.

## 6. Правила содержания

- Язык владельца и заказчика: «Петрович отвечает по данным парка», а не «добавлен `FleetAgent`». Имена классов,
  инструментов и веток — в `source`, в пояснениях шагов (как `list_vehicles` на слайде 11) и в заметках.
- Каждое утверждение — из коммита, журнала или документа. Не видно — не пишите. Работает только в демо-режиме,
  только в ветке или только со стендом — так и скажите.
- Ограничения не прячьте: «в тестах модель подменена — на реальной LLM качество ещё не мерили» — образец.
- Строки кода — только мелким числом на слайде «что сделали» с оговоркой, по какой ветке посчитано.
- Гипотезы и цели BRD — с той же оговоркой; гипотеза остаётся в `[скобках]`.
- Секреты, адреса стендов, логины и токены на слайды и в заметки не переносите.
- **Заметки докладчика** (`notes`) — то, что говорит выступающий: 4–8 предложений связным текстом, полными
  словами («служба безопасности», а не «СБ»), без чтения слайда вслух. Объясняют, почему так и что важно;
  оговорки про ветки и ограничения повторяются и здесь.

## 7. Сборка и ответ

1. `npm run sprint-deck -- slides/sprint_<N>.json` — схема, нейрослоп, сборка `.pptx` и превью, проверка вёрстки
   в безголовом Edge или Chrome. Нужен ВЕРДИКТ: ПРОШЛО. «Впритык» — сократите текст: PowerPoint верстает чуть
   иначе браузера. Нет браузера — «НЕ ПРОВЕРЕНО», так и скажите пользователю.
2. `/deslop` по JSON (тексты слайдов и заметки), затем пересобрать.
3. `npm run check` — сверяет версии в `sources` и что `.pptx` собран из текущего JSON.
4. Есть PowerPoint — посмотрите слайды глазами: выгрузка в PNG через COM
   (`$app = New-Object -ComObject PowerPoint.Application`, `Presentations.Open(<путь>, -1, 0, 0)`,
   `Slide.Export(<png>, "PNG", 1600, 900)`; `Quit()` — только если PowerPoint не был запущен до этого).
   PNG — в папку для временных файлов, не в `slides/`.
5. Ответ пользователю: путь к `slides/sprint_<N>.pptx`, превью `slides/sprint_<N>.preview.html`, диапазон коммитов,
   итог «план против факта» одной строкой (счёт), что в ветках без мерджа, вопросы, которые стоит закрыть до защиты.
   Ничего не коммитить без подтверждения.
