## 2. Данные по экранам

| Экран | Что нужно | Откуда |
|---|---|---|
| 3.1 Первый запуск | Машины, связь, молчащие датчики, история за период, первые находки | AutoGRAPH; находки считают правила |
| 3.2 Главная | Число проблем, на линии / стоят / без связи, время данных, новые события, виджеты | Телеметрия последней проверки, лента событий |
| 3.3 Уведомления | Заголовок, текст, уровень, время, прочитано ли, ссылка на событие | Петрович (на телефоне) |
| 3.4 Доклад | Итог фразой, топливо, пробег, холостой ход, заправки за 24 ч, список случаев | AutoGRAPH + лента событий |
| 3.5 Проблемы | Событие: машина, тип, уровень, время, вывод, статус | Лента событий |
| 3.6 Карточка события | Значение, график параметра ±3 ч, скорость и зажигание в момент события, прошлые случаи, что делать | AutoGRAPH + история разборов |
| 3.7–3.10 Разбор, звонок, письмо, итог | Контакт (имя, роль, телефон, почта), журнал разбора, итог, меры | Настройки владельца + журнал |
| 3.11 Чат | Ответ, кнопка действия, черновик письма | Локальные правила или LLM на стенде |
| 3.12 Парк | Машины: номер, модель, база, статус, последняя связь, пробег за сегодня | AutoGRAPH |
| 3.13 Карточка машины | В баке, пробег и холостой ход за период, связь, датчик топлива | AutoGRAPH |
| 3.14 Карта | Трек, стоянки, геозоны | **Нет источника** — Q-17 |
| 3.15–3.16 Виджеты | Показатель за период, изменение к прошлой неделе, лидеры | AutoGRAPH |
| 3.17 Настройки | Время и дни доклада, голос, тихие часы, лимит push, контакты | Вносит владелец, хранится на телефоне |

Сущности:

```
Статус парка: { проблем, на_линии, стоят, без_связи, данные_на }
Событие: { id, машина, тип, уровень, время, параметр, значение, вывод, статус,
           кому_передано, итог, меры[], причина_ложной, журнал[], решил, когда_решил }
Машина: { id, номер, модель, база, статус, в_баке, пробег, холостой_ход, последняя_связь, датчик_топлива }
Доклад: { итог, топливо_л, пробег_км, холостой_ч, заправки, случаи[] }
Контакт: { имя, роль, телефон, почта }
```

Статусы события: новое → в работе → закрыто (подтверждено или ложная тревога); «Вернуть» снова делает событие
новым. Уровни: «Срочно», «Внимание», «Мелочь».

## 3. Правила расчёта, которые уже заданы в коде

- **Статус машины:** «на линии» — едет по последней точке, «стоит» — на связи и не едет, «без связи» — нет
  свежих данных. Считается при каждой проверке, а не в реальном времени.
- **Цвет главной:** красный — есть новые срочные; жёлтый — срочных нет, есть новые замечания; зелёный — замечаний
  нет; нейтральный — «Ещё не проверял данные».
- **Пороги событий** — фиксированы в коде, таблица в `app_implementation.md` v0.1, §4. Интерфейса настройки нет
  (Q-29).
- **Проверка:** каждые 15 мин за последние 3 ч.
