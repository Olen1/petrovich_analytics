# Мобильная аналитика: данные по экранам (MVP, 5 спринтов)
_Статус: черновик | Версия: 0.2 | Дата: 2026-09-16_

---

## 1. Назначение

То же, что в `mobile_analytics_screens.md`, но короче: какие поля нужны на каждом экране, без описания UI. Скоуп — только MVP на 5 спринтов, лишнее не включено (см. `mobile_analytics_screens.md` §5).

---

## 2. Данные по экранам

| Экран | Что нужно от бэкенда |
|---|---|
| Главный экран | Цвет статуса парка, число аномалий (High/Med/Low) за сутки, время последнего обновления |
| Отчёт | Текст дайджеста, список из 2–3 главных аномалий |
| Список аномалий | Список: ТС, тип, серьёзность, короткое описание, статус |
| Карточка аномалии | Описание, вероятная причина, рекомендация, статус, кнопки решить/отклонить |
| Чат | Ответ на текстовый или голосовой вопрос (потоково), пометка, если это упрощённый режим без LLM; настройка «озвучивать ответ» (вкл/выкл, хранится на устройстве) |
| Push | ТС, серьёзность, короткое описание, ссылка на карточку аномалии |

Три сущности — не больше:

```
Статус парка: { цвет, high, med, low, обновлено_в }
Аномалия: { id, ТС, тип, серьёзность, статус, описание, причина, рекомендация }
Отчёт: { текст, топ_проблемы[] }
```

## 3. Правила, которые нужно уточнить до разработки

- Как считается цвет статуса парка (red при любой High-аномалии? при скольких?).
- Кто задаёт пороги серьёзности — фиксированные на старте или настраиваемые.
- Как быстро статус аномалии (решена/отклонена) синхронизируется с веб-версией для аналитика.
- Движок распознавания/синтеза речи для голосового ввода и озвучки в чате: on-device или облачный (влияет на офлайн-доступность голоса) — см. открытый вопрос в `mobile_analytics_screens.md` §8.

Остальные открытые вопросы по данным (история, несколько парков и т.д.) отложены — см. `mobile_analytics_screens.md` §6, они не входят в 5 спринтов.

> Этот документ описывает данные в объёме версии 0.2 экранного документа; экранный документ обновлён до 0.4 (добавлены финансовая оценка потерь, доказательства аномалий, ложные тревоги, голос в чате) — при следующей правке стоит синхронизировать оба файла полностью.
