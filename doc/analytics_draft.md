# Черновик аналитики: ИИ-агент «Петрович»
_Статус: черновик | Версия: 0.3 | Дата: 2026-09-12_

---

## 1. Контекст и границы системы

**Клиент:** Техноком (и парки других компаний через пуллинг)
**Парк:** ~10 000 ТС, ХМАО/Ямал/Пермский край
**Дороги:** промысловые (низкое качество покрытия, частые потери сигнала)
**Режим работы:** 24/7, телематика в режиме реального времени
**Источник телематики:** AutoGRAPH.NET (`https://web.tk-ekat.ru/ServiceJSON/`) — REST-подобный API, 192 метода, авторизация по токену сессии
**Каналы взаимодействия с агентом:** Telegram, корпоративная система MAX, адаптивный веб

**Три уровня архитектуры:**
| Уровень | Роль | Ключевые данные |
|---|---|---|
| Телематика | Сбор сырых данных с ТС через AutoGRAPH API | GPS, CAN, топливо, датчики, рейсы, геозоны |
| ML | Прогнозирование, детекция аномалий, скоринг | Агрегаты по ~10 000 ТС |
| LLM (Петрович) | Интерпретация, диалог с пользователем | Запросы на естественном языке, стриминг |

## 2. Зафиксированный функционал

### Реализовано в MVP
- Загрузка данных: файл xlsx/csv (Skaut, Omnicom) **и** прямой коннектор к AutoGRAPH API
- График топлива + моточасов (сырые точки) с навигацией по диапазонам
- График дневных агрегатов: факт vs прогноз расхода
- Карта трека через 2ГИС
- Таблица по дням: пробег, расход, прогноз, отклонение %, холостой ход, л/моточас
- Экспорт в CSV
- Детектор аномалий: три уровня (High/Med/Low), жизненный цикл (New/Resolved/Dismissed)
- LLM-чат со стримингом, fallback-режим без LLM
- Ежедневные Telegram-отчёты по расписанию (09:30 Asia/Yekaterinburg)
- Backend: PostgreSQL + REST API со Swagger-документацией

### Запланировано
- Специализированные правила фрод-детекции (топливо — приоритет №1)
- Полноценная ML-прогнозная модель
- Мобильное приложение с голосовым помощником
- Ролевая модель и admin-панель
- Пуллинг данных от 10 000+ ТС

## 3. AutoGRAPH API — что важно для интеграции

### Ключевые факты
- **192 метода**, организованы по группам: аутентификация, данные по приборам, свойства, отчёты, ТО, администрирование
- Авторизация: `Login` → токен сессии → параметр `session` в каждом запросе; **401 без тела** при невалидном токене
- Каждый метод требует `schemaID` (ID организации) — получается через `EnumSchemas`, кэшируется навсегда
- Идентификаторы объектов — **GUID**, списки передаются через запятую в одной строке

### Методы, релевантные для Петровича
| Задача | Метод AutoGRAPH |
|---|---|
| Список ТС с иерархией групп | `EnumDevices` |
| Текущее положение и статус | `GetOnlineInfo` / `GetOnlineInfoAll` |
| Трек (GPS + скорость) | `GetTrack` |
| Рейсы + отрезки + агрегаты | `GetTrips` / `GetTripsOnly` / `GetTripsTotal` |
| Детальные значения параметров по точкам | `GetTripItems` |
| Список водителей | `EnumDrivers` |
| Геозоны | `EnumGeoFences` / `GetGeofences` |
| Плановые сервисные работы (ТО) | `EnumServiceWorks` |
| Выполненные ТО | `EnumServiceMaintenance` |
| Счётчики (пробег, моточасы) | `GetCountersValues` |
| Правила мониторинга (алерты в системе) | `EnumMRules` |
| Свойства ТС (госномер, тарировка, водитель) | `GetProperties` / `SetProperties` |
| Отчёты (PDF/Excel) | `GetReport` / `EnumReports` |

### Критические нюансы API
- **Три режима времени в одном API**: методы данных используют `UTCOffset` из `Login`; методы свойств (`SetProperties`) — локальное время без UTC; биллинг — всегда UTC. Главный источник ошибок интеграции.
- **Формат трека** — не массив точек, а параллельные массивы `DT[]`, `Lat[]`, `Lng[]`, `Speed[]` — сборка на клиенте.
- **Объём ответов** — при запросе `tripParams=null` (все параметры) за месяц по 100+ ТС ответ может достигать сотен МБ. Всегда указывать явный список нужных параметров.
- **HTTP 401 без JSON** — клиент не получит описание ошибки, нужно обрабатывать по коду.

## 4. Открытые вопросы

### 4.1 Данные и телематика

- [ ] **Частота опроса.** ~450 точек/день на 1 ТС (~1 точка каждые 3 мин) — расчёт по сырым данным. Это стандарт для всего парка или зависит от режима (движение / стоянка)?
- [ ] **Потери сигнала.** Промысловые дороги — частые GPS-потери. AutoGRAPH возвращает пары `DT`/`DTLocal` и `SD`/`SDLocal` — как обрабатываются gaps? Интерполяция, заморозка, флаг?
- [ ] **CAN vs датчик топлива.** В данных оба источника — какой считается достоверным при расхождении? AutoGRAPH поддерживает тарировочные таблицы (`TareTable` в свойствах) — они настроены?
- [ ] **ТС без CAN.** Старая техника без CAN-шины — поведение системы при отсутствии CAN-данных?
- [ ] **Хранение истории.** PostgreSQL в MVP — где живут сырые данные AutoGRAPH? Срок хранения? Нужна ли репликация в собственное хранилище для ML?
- [ ] **Параметры схемы.** `EnumParameters` возвращает список параметров, специфичных для схемы Техноком — какие параметры настроены? Это ключ к пониманию доступных метрик.

### 4.2 ML-модели

- [ ] **Прогноз в MVP.** В таблице уже есть колонка «Прогноз, л» — чем он считается сейчас? Скользящая средняя? Если да, это и есть первая гипотеза для замены на ML.
- [ ] **Целевые метрики.** Приемлемый % ложных срабатываний (false positive) для фрод-алертов? Высокий FP убивает доверие к системе.
- [ ] **Холодный старт.** Новый клиент без истории: работает на агрегированном пуле или нужен период адаптации?
- [ ] **Сезонность.** Нормы расхода зима/лето принципиально разные. Сезонные факторы учтены?
- [ ] **Тип дороги.** Промысловая vs. асфальт — фактор учитывается? AutoGRAPH имеет геозоны (`EnumGeoFences`) — можно ли по ним определять тип маршрута?
- [ ] **Переобучение.** Как часто модели переобучаются? Batch или онлайн?

### 4.3 LLM-агент (Петрович)

- [ ] **Какая LLM?** В MVP есть флаг «Использовать LLM» — что именно подключено? On-premise или облако? Критично для privacy: телематические данные не должны уходить в публичное облако без согласования.
- [ ] **Что в промпте.** Агент получает сырые точки или только агрегаты/выводы ML? При 10 000 ТС сырые данные в контекст не влезут.
- [ ] **Fallback-режим.** При `useLlm=false` — что происходит? SQL напрямую? Шаблонный ответ? Это важно для SLA.
- [ ] **Уровень автономии.** Агент действует (создаёт задачи, отправляет уведомления) или только рекомендует?
- [ ] **Guardrails.** Как верифицируются числа в ответах — галлюцинации с конкретными цифрами по топливу критичны.

### 4.4 Пользователи и роли

- [ ] **Роли в системе.** AutoGRAPH имеет собственную систему ролей (`EnumRoles`, `RUser` с `IDRoles[]`, `Restrictions`). Петрович наследует эти роли или строит свою модель доступа?
- [ ] **Разграничение видимости.** Диспетчер видит свою колонну, директор — весь парк? `EnumDevices` поддерживает `parentIDs` для ограничения дерева.
- [ ] **Два сегмента.** Аналитик (веб, детальные таблицы) и владелец (мобильное, «есть проблема/нет») — разные продукты, разные промпты, разная детализация ответов агента.

### 4.5 Интеграции

- [ ] **AutoGRAPH — реальный API или mock?** Коннектор в MVP уже есть (вкладка «AutoGRAPH» в загрузке) — он работает с `web.tk-ekat.ru` или это заглушка?
- [ ] **Обработка 401.** AutoGRAPH возвращает 401 без тела при истечении токена. Реализован ли автоматический re-login?
- [ ] **Система MAX.** Что это — собственная разработка Техноком? Нужна двусторонняя интеграция?
- [ ] **ERP/1С.** Данные о заправках и путевых листах — подтягиваются для сверки с телематикой?
- [ ] **Алертинг реального времени.** AutoGRAPH имеет правила мониторинга (`EnumMRules`) — Петрович их читает и транслирует, или строит свои?
- [ ] **Правила мониторинга AutoGRAPH** (`EnumMRules`) — они уже настроены у Техноком? Какие? Это готовый список аномалий-кандидатов.

### 4.6 Бизнес-метрики и успех

- [ ] **KPI.** Снижение расхода топлива на X%, N выявленных случаев фрода, рост NPS?
- [ ] **Baseline.** Есть данные «до Петровича» для сравнения?
- [ ] **ROI.** В концепции агент считает ROI — от каких исходных данных (стоимость топлива, норма расхода, штрафные тарифы)?

### 4.7 Безопасность и compliance

- [ ] **ПДн водителей.** `EnumDrivers` возвращает ФИО — оценка вождения привязана к физлицу. Согласия на обработку ПДн есть?
- [ ] **Конфиденциальность данных Техноком.** AutoGRAPH — корпоративная система. Данные нельзя передавать в публичный LLM без явного согласования.
- [ ] **Аудит-лог.** Все запросы к агенту и ответы логируются? Срок хранения?
- [ ] **SLA и fallback.** Что при недоступности AutoGRAPH API? Что при недоступности LLM?
