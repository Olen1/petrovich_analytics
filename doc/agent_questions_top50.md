# 50 частых вопросов владельца к Петровичу
_Статус: черновик | Версия: 0.1 | Дата: 2026-10-20_

Пятьдесят вопросов, которые владелец парка вероятнее всего задаст Петровичу, и проверка по коду: ответит ли
на каждый локальный Петрович и Петрович на стенде. Сейчас локальный отвечает по сути на 11 из 50, стенд — на 21.
Ни один не отвечает на вопросы о деньгах, о месте машины и о водителе: этих данных нет.

**Частота — гипотеза.** Реальных логов чата нет: приложение не в пилоте, вопросы пользователей не собираются.
Список собран из источников ниже и упорядочен по предполагаемой частоте: ежедневные вопросы о состоянии парка —
выше, редкие о деньгах и ТО — ниже. Проверяется после пилота по записанным формулировкам (§5).

Источники: `brd_petrovich_mvp_full.md` v1.3 (B.2, §5), `brd_mobile_mvp.md` v0.3, `mobile_analytics_screens.md`
v1.0 (3.4, 3.6, 3.11), `CJM_Petrovich_v2.md` v2.0, `Problem Space.md` v1.0, `conkyrentnyy-analyz.md`,
`app_implementation.md` v0.1; код `../petrovich`: `chat/ChatAgent.kt` (локальный Петрович) и
`../petrovich/ml/fleet_service/README.md`, системный промпт и инструменты стенда.

## 1. Как читать таблицу

**Источник:** BRD — главный BRD; BRD0.3 — краткий BRD; ЭК — экраны v1.0; CJM — CJM v2.0; PS — Problem Space;
КА — конкурентный анализ; Код — подсказки и интенты локального Петровича; Г — гипотеза команды по сценариям
экранов, в документах дословно не встречается.

**Локально** — Петрович на телефоне, по умолчанию. Понимает вопрос по ключевым словам: «в порядке», «как дела»,
«не так», «недел», «кто больше», «связь», номер машины, «напиши/отправь + письмо/СБ/бухгалтер»; в карточке события
— «почему», «что случилось», «раньше», «доказ», «механик». Остальное — «Не уверен, что понял вопрос».

**Стенд** — «Ассистент через стенд»: LLM с инструментами `list_vehicles`, `get_vehicle_summary` (минимум,
максимум, среднее и последнее значение параметров машины), `check_vehicle`, `list_anomalies`, `get_anomaly`,
письма. Период — не длиннее 168 ч. Сам ничего не считает: только пересказывает данные инструментов.

✅ — отвечает по сути; ⚠ — отвечает частично или не на тот вопрос; ❌ — не отвечает или нет данных.

## 3. Итог

| | ✅ | ⚠ | ❌ |
|---|---|---|---|
| Локальный Петрович | 11 | 16 | 23 |
| Петрович на стенде | 21 | 16 | 13 |

Что мешает чаще всего:
1. **Локальный Петрович не понимает синонимы.** «Слив», «срочно», «вчера», «что делать», «сколько ждут решения»
   не распознаются. Номер машины перехватывает любой вопрос о ней: на «сколько в баке» и «где сейчас» он отвечает
   её неразобранными случаями. Слово «неделя» срабатывает раньше «у кого больше».
2. **Нет данных.** Рубли и выручка (11, 48–50), координаты (24), водитель (18, 35), ТО (40). Это не исправить
   формулировками — нужны новые источники.
3. **У стенда нет ответов по всему парку.** Инструменты отвечают по одной машине, поэтому вопросы «сколько на
   линии», «сколько потратил парк», «нет ли перегрева у машин» требуют сводки по парку.
4. **Период стенда — до 7 суток.** Вопросы «за месяц» (25, 44) охватить нельзя.

## 4. Как использовать список

- **Тестовый набор чата.** Прогонять все 50 вопросов после каждой правки ассистента и сравнивать с таблицей.
  Для требования B.7 (числа только из данных) — сверять каждое число в ответе с карточкой и сводкой.
- **Коридорный тест.** Задание 7 в `hallway_testing.md` v0.2 собирает живые формулировки — дописывать их сюда.
- **Приоритет доработок.** Вопросы 1–22 — вероятно, ежедневные: ❌ и ⚠ в них важнее, чем в 39–50.
