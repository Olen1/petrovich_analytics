# АвтоГРАФ Web: что есть у системы заказчика и чего не хватает «Петровичу»
_Статус: черновик | Версия: 0.1 | Дата: 2026-10-22_

АвтоГРАФ Web — кабинет диспетчера, а «Петрович» сейчас берёт из него 5 методов API из ~190. Главные пробелы
закрываются своими силами: координаты и живой статус машины (`GetOnlineInfoAll`), стоянки и превышения по отрезкам
(`GetTrips`, `GetStage`), объём бака (`GetProperties`). Водители, геозоны и ТО в API есть, но в схеме Сбера пусты —
это вопрос к «Техноком». Рублей и выручки в АвтоГРАФ нет совсем.

Источники: исходный код главной страницы АвтоГРАФ Web версии 2026.1.2.1 (учётная запись Сбера, получен
2026-10-21); `autograph_api_reference.md` (справочник Service API); `app_implementation.md` v0.1 (что сделано в
коде); `agent_questions_top50.md` v0.1 (номера вопросов №1–50 ниже — оттуда); `otchet_analiz_telemetrii.md`
(параметры CAN на реальном файле); `brd_petrovich_mvp_full.md` v1.4.

**Ограничение.** Интерфейс описан по коду страницы: какие панели и окна в ней заложены. Вживую он не
просматривался, поэтому что из этого реально включено и заполнено у заказчика — `[проверить]`.

## 1. Как устроен интерфейс

Кабинет рассчитан на экран от 1200 px. Экран собирается из панелей, их можно перетаскивать и закреплять.
Мобильной версии кабинета в коде страницы нет, есть только режим для встроенной карты в мобильных приложениях
Техноком.

**Шапка:** выбор организации и схемы, баланс, список модулей, полноэкранный режим, настройки схемы, справка со
ссылкой на API, язык, выход.

| Панель | Что показывает |
|---|---|
| Объекты (дерево машин) | Группы и машины с колонками: рег. номер, датчики, время последних данных. Цвет — свежесть данных: зелёный до 30 мин, жёлтый 30–120 мин, красный больше 120 мин |
| Карта | 50+ подложек (2ГИС, Яндекс, OSM и др.), положение машин, плеер трека с пропуском стоянок, линейка, маршрут, погода, цены на АЗС, кластеризация, выгрузка трека в json, kml, gpx |
| Рейсы | Таблица рейсов за период: пробег, время, топливо, итоги, делители рейсов |
| Отрезки | Вкладки: общая информация, геозоны, остановки, сигнал, питание, скорость, бак, датчики, нарушения, идентификаторы. Фильтр по длительности и расстоянию, заметки к отрезку, печать, выгрузка |
| Графики | Любые параметры по времени или пробегу |
| Информация, карточки свойств | Текущие значения датчиков, свойства машины и геозоны на дату |
| Правила мониторинга | Условие по параметру, объект или группа, расписание. Каналы: всплывающее окно, push, почта, SMS, Telegram, Max, Viber, WhatsApp |
| Журнал событий | Срабатывания правил с кнопкой «Решить»: кто, когда и с какого IP решил |
| Отчёты | По объектам (PDF, Excel, Word и др.), быстрые, по расписанию с рассылкой |
| Прочее | Фото с камер, поиск «кто был в этом месте», заметки и заметки на карте, тахограф (DDD), KPI, панорамы улиц, сообщения пользователям |

**Схема Сбера** (по данным страницы): 167 машин, 0 водителей, 0 геозон, 0 прицепного оборудования, 0 правил
мониторинга, 0 расписаний отчётов, 0 сервисных работ. Включены модули: отчёты по расписанию, правила,
сообщения. Панели KPI, поиска по месту и чата скрыты.

## 2. Что можно извлечь через API

Сейчас «Петрович» использует `Login`, `EnumSchemas`, `EnumDevices`, `EnumParameters`, `GetTripTables`.

| Данные | Метод | В «Петровиче» | В схеме Сбера |
|---|---|---|---|
| Машины, группы, параметры | `EnumDevices`, `EnumParameters` | Да | Есть |
| Значения параметров по рейсам | `GetTripTables` | Да, основной источник | Есть |
| Положение сейчас, скорость, адрес, последние значения | `GetOnlineInfo`, `GetOnlineInfoAll` | Нет | Есть `[проверить]` |
| Трек | `GetTrack`, раскраска — `GetTrackColorSettings` | Нет | Есть `[проверить]` |
| Рейсы и отрезки: стоянки, превышения, бак | `GetTrips`, `GetStage` | Нет | Отрезки настроены |
| Значения в каждой точке | `GetTripItems` | Нет | Есть |
| Свойства: рег. номер, марка, объём бака | `GetProperties` | Нет | Рег. номер выведен в дерево |
| Геозоны, рейсы по геозонам | `EnumGeoFences`, `GetGeofences`, `GetTripsCustom` | Нет | 0 геозон |
| Водители и карты | `EnumDrivers`, `GetDriverProperties` | Нет | 0 водителей |
| Правила мониторинга | `EnumMRules` | Нет | 0 правил |
| ТО и счётчики | `EnumServiceMaintenance`, `EnumServiceWorks`, `GetCountersValues` | Нет | 0 работ |
| Отчёты | `EnumReportSchedules`, `EnumReports`, `GetReport` | Нет | 0 расписаний |
| Заметки к отрезкам | `GetNotes` | Нет | `[проверить]` |
| Фото с камер | `EnumPhoto`, `GetPhotoFile` | Нет | `[проверить]` |
| Одноразовые ссылки | `OTLCreate`, `OTLDelete` | Нет | В интерфейсе выключено для учётной записи |
| Хранилище данных приложения | `DataEnum`, `DataLoad`, `DataSave` | Нет | — |
| Статусы машин («Снят с рейса» и т. п.) | `EnumStatuses`, `SetDeviceStatus` | Нет | Два статуса рейса заведены |
| Маршрут между точками | `GetRoute` | Нет | — |
| Поиск машины | `FindDevices` | Нет | — |

**Параметры CAN.** На реальном файле телеметрии (`otchet_analiz_telemetrii.md`) приборы отдают расход по CAN,
обороты, нагрузку на двигатель, температуры, моточасы, пробег до ТО. Модель «расход ~ обороты + нагрузка» дала
R² = 0,97. Какие из этих параметров приходят с фур Сбера, неизвестно: нужен `EnumParameters` по 2–3 машинам.

## 3. Чего не хватает «Петровичу»

### 3.1. Данные есть в API — можно сделать своими силами

| Чего нет | Что даст | Метод | Вопросы |
|---|---|---|---|
| Координаты и адрес | Строка «где» в карточке события и машины, карта 3.14 на реальных данных (сейчас заглушка) | `GetOnlineInfoAll`, `GetTrack` | №24 |
| Живой статус машины | Плитки «На линии / Стоят / Без связи» по трекеру, совпадают с цветами АвтоГРАФ (30 / 120 мин) | `GetOnlineInfoAll` | №7 |
| Стоянки и холостой ход по отрезкам | Простои (A-5), холостой ход по парку | `GetTrips`, `GetStage` | №21 |
| Превышения скорости и нарушения | Отрезки «Скорость» и «Нарушения» уже считает АвтоГРАФ | `GetStage` | — |
| Объём бака, рег. номер | «Слив больше бака — ошибка датчика»; номер вместо имени прибора | `GetProperties` | №13 |
| «Расход выше обычного» | Правило по CAN: расход против оборотов и нагрузки | `GetTripTables` с параметрами CAN | №20, Q-33 |
| Агрегаты по парку в чате | «Сколько потратил парк вчера», заправки за неделю | Расчёт на стенде, `GetTripsTotal` | №16, №19 |
| Доказательство для СБ | Одноразовая ссылка на трек в письме: где стояла машина во время слива | `OTLCreate` | — |
| Меньше ложных тревог | Машина «в ремонте» или «снята с рейса» — простой не считается проблемой | `EnumStatuses` | — |

Первый шаг — `GetOnlineInfoAll`: один метод закрывает «где машина», живой статус и карту.

### 3.2. Метод есть, данных в схеме нет — нужен заказчик

| Чего нет | Что нужно от «Техноком» | Вопросы |
|---|---|---|
| Водители | Завести водителей и карты (вкладка «Идентификаторы» уже есть) | №18, №35, Q-5 |
| Геозоны | Базы и АЗС как геозоны → «слив вне АЗС», «стоял не на базе» (A-3, A-4) | Q-17 |
| ТО и счётчики | Вести сервисные работы в АвтоГРАФ | №40 |
| Заметки диспетчера | Пользуются ли клиенты заметками к отрезкам: это готовое «что сказал водитель» | №35 |

### 3.3. Данных нет в АвтоГРАФ

- **Рубли.** Цены топлива в Service API нет. На карте кабинета есть цены на АЗС, но через API они не отдаются.
  Варианты: цена, которую вводит владелец, или внешний источник (Q-7).
- **Выручка.** В телематике её нет (№49, №50). Нужна интеграция с учётом заказчика или исключение из MVP.
- **Объяснение водителя, прочтение письма СБ** — данные самого «Петровича», хранить на стенде.

### 3.4. Что у АвтоГРАФ есть, а «Петрович» делает слабее

- **Уведомления в мессенджеры.** АвтоГРАФ шлёт события в Telegram и Max, «Петрович» — push и письмо. В
  `conkyrentnyy-analyz.md` и на слайде сравнения нужна пометка: функция у «Техноком» есть, у Сбера не настроена.
- **Журнал событий с «Решить»** — по смыслу наш «Разбор», но без вывода и советов.
- **История трека.** В АвтоГРАФ видно, где машина была в момент слива; у нас только график ±3 ч.

Чего у АвтоГРАФ нет: вывода простым языком, чата, утреннего доклада, антиспама. Эту нишу «Петрович» закрывает.

## 4. Что «Петровичу» не трогать

Изменение машин, водителей, геозон, профилей и свойств (`Set…`, `Delete…`, `Move…`), пользователи и роли,
права доступа, организации и шаблоны схем, биллинг, виртуальные деревья, команды и файлы на прибор
(`SendCommand`, `AddDeviceOutFile`). Это зона администратора. Принцип «Петрович только читает» стоит закрепить в
BRD. Возможные исключения — `DataSave` (своё хранилище) и `SetDeviceStatus`.

Второстепенно для MVP: тахограф, мультитрек и мобильные контрольные точки, прицепное оборудование и задачи,
агроучёт, погода, камеры скорости, панорамы, KPI, сообщения пользователям.
