# Бизнес-требования: MVP мобильного приложения «Петрович»
_Статус: черновик | Версия: 0.2 | Дата: 2026-09-16_

> Обновлено под срок **5 спринтов**. Синхронизировано с `mobile_analytics_screens.md` v0.4 — при расхождении в деталях экранов ориентироваться на тот документ, здесь фиксируются только бизнес-требования верхнего уровня.

---

## 1. Цель и контекст

**Проблема, которую решаем:**
Владелец автопарка подключён к системе телематики (AutoGRAPH и аналоги), но не пользуется аналитикой — слишком сложно разбираться. Для интерпретации данных нужен отдельный специалист. При парке в 10–50 машин это нерентабельно.

**Цель MVP:**
Дать владельцу парка инструмент, в котором за 10 секунд видно: всё хорошо или есть проблема, какая именно и сколько денег она стоит.

**Что это НЕ:**
- Не замена диспетчерской системе
- Не инструмент для аналитика (для него — веб-интерфейс, отдельный продукт)
- Не полноценный мониторинг в реальном времени

---

## 2. Целевой пользователь

**Владелец или директор автокомпании / транспортного предприятия**

| Характеристика | Описание |
|---|---|
| Парк | 5–200 ТС (фуры, грузовики, спецтехника) |
| Занятость | Не сидит за компьютером, большую часть дня — в разъездах |
| Техническая грамотность | Средняя и ниже. Не читает таблицы с сырыми данными |
| Главный вопрос | «Всё нормально? Где я теряю деньги?» |
| Текущая боль | Узнаёт о проблемах (слив топлива, простои) постфактум, когда ущерб уже нанесён |
| Устройство | Смартфон (Android / iOS), преимущественно Android в целевом регионе |

## 3. Ключевые сценарии (Jobs to be Done)

### Сценарий 1 — Утренний push-отчёт (основной)
Каждое утро в фиксированное время владелец получает push: «Вчера: N машин в норме, M требуют внимания, потери ≈ X ₽». Открывает приложение — видит тот же отчёт подробнее.

### Сценарий 2 — Отчёт по запросу
В течение дня владелец открывает приложение и нажимает кнопку «Получить отчёт» — получает свежую сводку за сутки.

**Ожидаемое время до первого результата:** ≤ 10 секунд после нажатия.

### Сценарий 3 — Входящий алерт по серьёзной аномалии
Система обнаружила аномалию High-уровня. Владелец получает push с кратким описанием (ТС, время, сумма потерь). Открывает карточку — видит доказательство (график или карту), место, время, сумму, рекомендацию.

### Сценарий 4 — Разбор и закрытие аномалии
Владелец разбирается в аномалии, при необходимости показывает доказательство водителю, отмечает результат: «кража подтверждена» или «ложная тревога» (с указанием причины в один тап).

### Сценарий 5 — Вопрос в свободной форме
Владелец спрашивает голосом или текстом: «Петрович, почему у Иванова вырос расход?» Агент отвечает понятным языком, без жаргона и таблиц; при необходимости включена озвучка ответа.

### Сценарий 6 — Первое подключение
Владелец подключает AutoGRAPH-аккаунт или загружает файл (временное решение для пилота) при первом запуске.

## 4. Функциональные требования MVP

### 4.1 Обязательно (without this — not MVP)

| # | Требование | Описание |
|---|---|---|
| F-1 | **Главный экран — статус парка** | Цветовой индикатор (зелёный/жёлтый/красный), число аномалий за 24ч, **оценка потерь за сутки ≈ ₽**. |
| F-2 | **Отчёт: push по расписанию + кнопка «Получить отчёт»** | Утренний push в фиксированное время (по умолчанию) и по запросу в любой момент. Текст с суммой потерь и топ-2–3 проблемами. |
| F-3 | **Список аномалий** | Карточки: госномер, водитель (если доступен), тип, серьёзность (High/Med/Low), время, оценка потерь ≈ ₽. |
| F-4 | **Детальная карточка аномалии** | Что произошло, когда и где (адрес), сколько стоило (₽), **доказательство** (статичный график/карта с бэкенда), вероятная причина, рекомендация. |
| F-5 | **Закрытие аномалии** | Кнопки «Кража подтверждена» / «Ложная тревога» с выбором причины в один тап (заправка/норма, рабочая поездка, ошибка датчика, другое). После отметки повторный сигнал того же типа по этому ТС за тот же интервал не присылается. |
| F-6 | **Push-уведомления** | Утренний отчёт — по расписанию. High-аномалия — мгновенно. Med/Low — только в утреннем отчёте. |
| F-7 | **Диалог с агентом (текст и голос)** | Чат для уточняющих вопросов по аномалии или по парку. Ввод текстом или голосом (распознавание речи). Переключатель «Голосовой ответ» — озвучка ответов агента, вкл/выкл на устройстве. |
| F-8 | **Авторизация** | Вход по логину/паролю. Токен сессии. |
| F-9 | **Подключение к источнику данных** | AutoGRAPH (URL, логин, пароль) или загрузка файла xlsx/csv — загрузка файла является временным решением для пилота, не целевым путём. |

### 4.2 Желательно, если останется время (nice-to-have)

| # | Требование | Описание |
|---|---|---|
| F-10 | **Список ТС** | Экран со списком машин и статусом каждой. |
| F-11 | **История аномалий** | Лента событий за 7–30 дней с фильтром. |
| F-12 | **Настройка расписания** | Пользователь сам меняет время утреннего push (в MVP — фиксированное время). |

### 4.3 Вне скопа MVP (следующие версии)

- Рейтинг/сравнительная аналитика по водителям
- Интерактивная карта трека (в MVP — только статичное изображение-доказательство)
- Переключение между несколькими парками у одного пользователя
- Итоги месяца и полный ROI-отчёт (в MVP — только оценка потерь за сутки и по аномалии)
- Карточка ТС с трендами
- Управление водителями, планирование маршрутов
- Интеграция с 1С / ERP

## 5. Нефункциональные требования

| Параметр | Требование |
|---|---|
| Время формирования отчёта | ≤ 10 секунд от нажатия до начала ответа агента |
| Платформы | iOS 15+ и Android 10+ |
| Офлайн-режим | Показ последнего сохранённого статуса и отчёта с меткой времени; без синхронизации действий офлайн |
| Язык | Русский |
| Push-уведомления | Доставка High-аномалий в течение 5 минут от момента обнаружения |
| Безопасность | Шифрование токена на устройстве, HTTPS для всех запросов |
| Голос (F-7) | Доступность офлайн зависит от выбранного движка распознавания/синтеза (см. Q-2) — не гарантируется в MVP |

## 6. Детектируемые аномалии (скоп MVP)

Приоритет — **топливо**. Список сознательно узкий, по убыванию приоритета:

| # | Тип | Серьёзность по умолчанию | Доказательство в карточке |
|---|---|---|---|
| A-1 | Слив топлива (резкое падение уровня без движения) | High | График уровня топлива с отмеченным падением |
| A-2 | Отказ / отключение датчика топлива | High | График с «разрывом» данных |
| A-3 | Поездка в нерабочее время / выходной | Medium | Точка начала и конца, пробег |
| A-4 | Съезд с маршрута / нецелевой пробег | Medium | Адрес отклонения, лишние км |
| A-5 | Простой с включённым двигателем | Low | Длительность, израсходованные литры |

Более широкий список (ТО, расходники, стиль вождения, скорость) — после MVP. Пороги серьёзности — фиксированные на старте (см. Q-3).

**Оценка потерь в ₽** = литры × средняя цена топлива (константа на парк, задаётся на бэкенде), в интерфейсе всегда с пометкой «≈».

## 7. Архитектурные ограничения

- Мобильное приложение — **тонкий клиент**: детекция аномалий, расчёт потерь, генерация доказательств (график/карта) и ответов агента — на бэкенде.
- Бэкенд **общий** с веб-интерфейсом (MVP.html) — переиспользовать существующие эндпоинты.
- Коннектор к AutoGRAPH уже реализован в бэкенде — переиспользовать.
- LLM-агент — на бэкенде, мобильное приложение получает готовый текстовый ответ; для голоса нужен отдельный движок распознавания/синтеза (см. Q-2).
- Push-уведомления: Firebase Cloud Messaging (Android) + APNs (iOS).

## 9. Критерии готовности MVP

MVP считается готовым, когда владелец парка может:

1. Установить приложение и подключить свой AutoGRAPH-аккаунт (или загрузить файл) за < 5 минут
2. Получить утренний push-отчёт с суммой потерь ≈ ₽ и по запросу — свежий отчёт в любой момент
3. Увидеть список аномалий и открыть карточку с доказательством, временем, местом и суммой
4. Отметить аномалию как «кража подтверждена» или «ложная тревога» с причиной
5. Получить push-уведомление при критической аномалии в течение 5 минут
6. Задать уточняющий вопрос агенту текстом или голосом и, при включённой озвучке, услышать ответ
