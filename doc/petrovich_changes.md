## Сводка на 2026-10-09

- Android-приложение: навигация «Главная / Парк / Петрович / Проблемы / Настройки», карточка события, «Разбор» с
  действиями (звонок, письмо, закрытие), локальный чат по правилам, тихие часы и лимит push.

  телеметрия, правила аномалий, хранилище решений, фоновая проверка без телефона, отправка писем.
- Каждая функция стенда включается в приложении отдельным переключателем. По умолчанию приложение работает
  без стенда, как раньше.

### 2026-10-09 · PR #4 `fleet/step-6` · Knohhon
Коммиты: `a667863`, `12636b3`, слияние `7f885d1`, `7aa8c04`

**Что изменилось**
- Стенд, шаг 5 — фоновая проверка: стенд сам проверяет машины по расписанию (по умолчанию каждые 15 мин за
  последние 3 ч), даже когда телефон выключен. Приложение в фоне забирает ленту со стенда и уведомляет о новом.
  Одна аномалия даёт одно уведомление на все устройства пользователя.
- Доступ стенда к AutoGRAPH: по умолчанию токен сессии от приложения. Пароль уходит на стенд только при
  включённом «Разрешить стенду входить самостоятельно» и хранится зашифрованным. Выключение переключателя,
  демо-режим или смена адреса стенда отзывают доступ.
- «Главная»: карточка «Стенд давно не проверял данные», если AutoGRAPH или стенд недоступны.
- Стенд, шаг 6 — письма: Петрович в чате готовит черновик (получатели из списка на стенде, тема, текст),
  письмо уходит только по кнопке «Отправить». Адрес вне списка указать нельзя, ассистент сам не отправляет.
  Отказ стенда (истёк срок черновика, лимит писем) показывается в черновике.
- Настройки стенда перенесены в «Подключение и данные»: «Письма из чата», «Фоновая проверка на стенде».

**Затрагивает аналитику**
- `brd_petrovich_mvp_full.md` (версия 1.2 на момент записи), модуль D.4 и FR-D-34 — отправка писем реализована, в BRD приоритет C.
  Принцип «Петрович предлагает, человек подтверждает» (§4, модуль D) в коде соблюдён.
- `brd_petrovich_mvp_full.md` (версия 1.2 на момент записи), Q-6 (email: получатели, шаблоны, почтовый сервис) — в коде SMTP и список
  получателей в файле на стенде. Вопрос можно закрыть или уточнить у PO.
- Хранение пароля AutoGRAPH на стенде — в BRD нет требования. Нужна строка в NFR по безопасности.

  звонить и писать». Раз в сутки после назначенного времени — push-доклад (точность до 15 мин).
- Слияние со стендом: при «Ассистент через стенд» отвечает LLM стенда, иначе локальный Петрович.

### 2026-10-07…09 · PR #3 `fleet/step-4` · Knohhon
Коммиты: `3556ab6`, `4a01dc1`, `2e4f7fc`, `57ab328`, `0d859cb`, `aa4cc4d`, слияние `1bd00b4`

**Что изменилось**
- Появился стенд `ml/fleet_service` (FastAPI) — серверная часть «Петровича». Шаги 1–4 плана переноса.
- Шаг 1 — чат: вопрос из приложения уходит на стенд, отвечает LLM через OpenRouter. В приложении —
  адрес стенда и переключатель «Ассистент через стенд». Из карточки аномалии чат получает её контекст.
- Шаг 2 — телеметрия: стенд сам ходит в AutoGRAPH (EnumDevices, EnumParameters, GetTripTables) и отдаёт
  агрегаты. Ассистент получает инструменты «список машин» и «сводка по машине». В приложении —
  переключатель «Данные через стенд».
- Шаг 3 — правила: на стенд перенесён детектор аномалий из приложения, результат совпадает (проверено на
  эталонах). Подключена ML-модель `predictive_antifraud`; её сбой не ломает правила. Переключатель
  «Аномалии со стенда».
- Шаг 4 — хранилище: аномалии и решения владельцев хранятся на стенде (SQLite). В карточке видно, кто и когда
  принял решение. История с устройства переносится на стенд. Ассистент видит ленту аномалий.
  Переключатель «Хранить аномалии на стенде».
- Документация: `../petrovich/ml/fleet-step-4-deviations.md` (отклонения шага 4 от плана), `../petrovich/ml/MANUAL_CHECK.md` (ручная
  проверка на реальных данных).

**Затрагивает аналитику**
- `brd_petrovich_mvp_full.md` (версия 1.2 на момент записи), Q-1 и NFR-S8 — данные уходят во внешний LLM через OpenRouter. В BRD это
  блокирующий вопрос к заказчику.
- `brd_petrovich_mvp_full.md` (версия 1.2 на момент записи), жизненный цикл аномалии — у решения на стенде есть автор. Для метрики
  «Problem resolution rate» (§2.2) это источник данных.
- `../petrovich/ml/fleet-step-4-deviations.md` — стоит прочитать при сверке BRD с реализацией.
